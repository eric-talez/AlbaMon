# K-Work US 운영 검토 / Moderation runbook

적용 범위: 캘리포니아 공고, 무료 구인·구직 첫 출시. 아래는 구현된 운영 절차다. 실제 운영 책임자, 대체 담당자, 지원 메일·공개 도메인, 정책 승인과 대표 리허설은 아직 **UNVERIFIED**이며 공개 전 확정해야 한다. 로컬 기술 리허설은 실제 대표의 승인이나 운영 인수인계를 대신하지 않는다.

## 접수와 우선순위

일반 접수의 첫 응답 목표는 **1영업일**이다. 해결 시간의 보장이 아니다. 신고 큐의 기본 화면은 열린 신고를 오래된 접수부터 20개씩 보여준다. 공고·회사·권한 요청도 대기 항목부터 확인하고 다음 페이지를 넘긴다. 공개 공고의 사기·위협·금전 요구는 즉시 대응 우선순위다.

담당자가 부재하면 지정된 대체 담당자가 MFA로 로그인해 대기 큐와 지연을 확인하고 접수 응답을 보낸다. 대체 담당자가 없으면 신규 공고 승인과 공개 확대를 보류한다. 자동 승인이나 검토 완료 일괄 처리를 하지 않는다. 실제 책임자·대체 담당자·지원 채널이 미지정인 현재 상태에서는 이 약속을 외부에 게시하지 않는다.

## 공고 체크 순서

1. 근무지가 실제 CA인지 확인한다. 직무·업무 장소·근무 시간·고용 형태가 서로 일치하는지 읽는다.
2. 시급/연봉 단위와 최저·최고 범위, 기본급과 팁의 구분을 확인한다. 현지·업종별 임금 기준은 담당자가 최신 공식 자료로 확인한다. 급여 누락·허위 범위·팁으로 기본급을 대체하는 설명은 승인하지 않는다. 캘리포니아 급여 공개 의무의 구체적 적용 범위는 [DIR 안내](https://www.dir.ca.gov/dlse/california_equal_pay_act.htm)를 확인한다.
3. 직무·책임·요건이 구체적인지 확인한다. 지원자에게 보증금·교육비 선입금·기프트카드·은행 인증번호를 요구하거나 개인 메신저로만 이동시키는 공고는 중지하고 조사한다.
4. 국적·민족·인종을 자격으로 제한하지 않는다. “한국인만”, “특정 국적 제외”는 반려 예시다. “한국어 고객 상담 업무를 위해 한국어로 전화 응대 가능한 분”은 실제 직무상 필요를 설명하는 허용 가능한 표현의 예시다. 언어 능력 수준은 실제 업무와 연결되어야 한다. 출신·억양을 능력의 대용으로 판단하지 않는다. [EEOC 지침](https://www.eeoc.gov/laws/guidance/eeoc-enforcement-guidance-national-origin-discrimination)을 참고한다.
5. “현금만 지급, 세금 신고 없음”, “신분에 따라 다른 급여”, 성별·나이·출신에 따른 부당한 제한 등 위험 문구는 사실을 확인하고 수정 전 공개하지 않는다. 현금 지급이라는 단어만으로 위법이라고 단정하지 않는다.
6. 회사명·실제 주소·웹사이트·연락처를 대조한다. 독립적으로 찾은 공식 웹사이트의 대표 연락처로 사업 및 모집 담당자의 권한을 확인한다. 제출한 전화번호나 등록증 이미지 하나만 신뢰하지 않는다. 등록기관 자료·영업 정보와 확인 날짜·출처를 운영 기록에 남긴다. 불필요한 신분증·주민번호는 수집하지 않는다.
7. 회사 확인 배지는 회사 정보 확인 결과일 뿐, 모든 공고의 안전·합법성 보증이 아니다. 회사 확인과 공고 위험 검토를 각각 처리한다. 승인 후에도 내용 수정은 다시 검토 대기로 돌아가며 공개 기간은 B2 규칙을 따른다.

## 신고에서 실제 중지까지

1. `/admin/reports`에서 신고 상세와 관련 공고를 연다. 신고자 이름·이메일은 관리자 조사 용도로만 사용한다. 고용주 화면, 중지 사유, 이메일에 신고자 신원이나 신고 원문을 복사하지 않는다.
2. 즉시 중지 조건(사기성 선입금, 위협, 신원 도용 의심, 차별적 자격 제한, 허위 급여·직무, 반복 스팸)이면 공개 공고의 **공고 중지 후 검토 완료 / Pause and review**에 1~500자의 사실 중심 사유를 적는다. 이 작업은 해당 신고와 연결된 공고를 서버에서 조회하고 B2 상태 전환·수정 시각 비교를 사용한다. 성공하면 공고 중지 감사 기록을 남긴 뒤 신고를 reviewed로 처리한다.
3. 충돌 메시지가 나오면 새로고침해 공고와 신고를 각각 확인한다. 다른 담당자가 먼저 처리했을 수 있고, 공고는 중지됐지만 신고 상태 처리가 충돌했을 수도 있다. 이미 중지된 공고는 상태만 검토 완료로 정리할 수 있다.
4. **검토 완료 (상태만)**·**기각**은 신고 상태만 변경한다. 이것만으로 공고가 내려가지 않는다. 해당 화면도 이 사실을 명시한다. 단순 검토 완료를 제재 완료라고 회신하지 않는다.
5. 반복 악용이면 `/admin/users`에서 계정을 찾아 사유를 기록하고 정지한다. 자기 계정 정지는 허용하지 않는다. DB의 현재 active 상태와 admin+AAL2가 최종 권한이다. 정지는 기존 JWT의 새 쓰기도 차단하고 해당 계정의 대기·공개 공고를 같은 트랜잭션에서 중지한다. 역할을 구직자로 바꾸는 방식으로 제재하지 않는다. 기존 지원·대화 읽기는 남는다.

## 회신과 이의신청

반려 예시: “공고에 직무와 무관한 국적 제한이 있어 공개를 보류했습니다. 실제 업무에 필요한 한국어 상담 능력으로 요건을 구체화하고 다시 제출해 주세요. / Please describe the language skills needed for the actual work and resubmit.”

중지 예시: “지원자에게 선입금을 요구하는 내용이 확인되어 공고를 중지했습니다. 모집 절차와 비용 요구에 대한 설명을 보내 주세요. 신고자 정보는 공개하지 않습니다. / This listing is paused while we review the payment request.”

이의신청은 공개 전 확정할 지원 채널로 접수한다. 사건/공고 ID, 이의 사유, 수정 사항과 독립 검증 가능한 자료만 요청한다. 다른 담당자가 가능하면 최초 결정을 재검토하고 판단 근거를 남긴다. 현재 실제 지원 주소는 미정이며 가짜 주소를 안내하지 않는다. 승인 없이 외부에 답변을 보내지 않는다.

## 복구와 운영 이력

계정 복구는 별도의 **정지 해제 / Restore**에 해제 사유를 입력한다. 기존 공고는 자동 재공개되지 않는다. 고용주가 수정·재제출하고 관리자가 공고별로 다시 승인한다. 과거 운영/서비스 작업으로 정지 계정에 approved 상태가 남았더라도 복구는 이를 paused로 정리한다. 활성 관리자도 정지된 소유자의 공고를 승인할 수 없다.

계정 페이지의 최근 20개 운영 이력에서 actor, 대상, 시각, 정지·해제 이유를 확인한다. 회사 확인, 고용주 권한 결정, 신고 결정도 DB 감사 기록에 남는다. 공고 감사 기록은 B2 단일 writer가 작성한다. UI에서 감사 로그를 수정·삭제하지 않는다. 상세 이력 확인은 허용된 관리자 조회로 수행한다.

## 쓰기 한도 및 리허설

한도는 계정 기준 이동 시간창으로 적용된다: 공고 5/24시간, 지원 30/24시간, 메시지 20/60초 및 200/24시간, 신고 10/24시간, 고용주 권한 요청 3/24시간. API 우회·임의 과거 시각으로 한도를 회피할 수 없다. 한도 도달 안내는 “잠시 후 다시 시도해 주세요”이며 DB 오류 원문을 전달하지 않는다. 정지와 겹치기 전에 승인된 쓰기가 먼저 끝날 수 있지만, 정지 완료 후 새 쓰기는 실패하고 승인·대기 공고는 남지 않는다.

로컬 리허설: 실제 Auth 계정으로 admin AAL1 거절→MFA AAL2→신고 상세→B2 사유 중지→reviewed→계정 정지→오래된 사용자 세션의 REST 쓰기 거절→기존 내역 읽기→별도 복구→공고 비공개 유지→감사 기록 확인을 실행한다. 각 fixture ID만 정리하고 outbox/audit 잔여를 확인한다. 실제 이메일을 보내지 않는다. 대표는 공개 전에 동일 절차와 부재 시 인계·이의신청 회신을 직접 리허설하고 날짜·승인자를 별도 출시 증거에 기록해야 한다.
